# 学習進捗トラッカー

依存パッケージ・外部API・CDNのない、日本語の静的PWAです。Phase 1（書籍管理・進捗計算・保存・PWA）とPhase 2（履歴・グラフ・時間・バックアップ）を実装しています。

## ローカル起動

Node.js 22以上で、リポジトリ直下から実行します。パッケージのインストールは不要です。

```sh
npm test
npm run build
npm start
```

http://127.0.0.1:4173/study-tracker/ を開きます。サブパスとルートの両方に対応します。ファイルの直接オープンはES Modules・Service Workerが動かないため利用できません。

## GitHub Pagesへの公開

1. このフォルダの中身（隠しフォルダ `.github` も含む）をGitHubリポジトリのルートへ配置します。
2. mainブランチへpushします。
3. Settings → Pages → Build and deployment → Source を **GitHub Actions** にします。
4. Actionsの「Deploy GitHub Pages」を実行するか、mainへ再度pushします。
5. 成功後、ワークフローのdeployment URLを開きます。

すべての配信パスは相対パスです。通常、リポジトリ名変更時も設定変更は不要です。ブランチ名を変える場合は `.github/workflows/pages.yml` の `branches` を変更してください。サーバー・認証設定は不要です。公開先: https://hypoballad.github.io/study-tracker/ 。ソース: https://github.com/hypoballad/study-tracker 。

## Android（Google Pixel）

公開URLをChromeで開き、初回読み込み後、メニュー →「ホーム画面に追加」→「インストール」。対応時はアプリ下部にも追加ボタンが表示されます。一度オンラインで読み込んでからオフラインで起動してください。インストールはHTTPS（ローカル開発はlocalhost例外）が必要です。

## 記録と計算のルール

- 開始ページは学習開始時の基準位置。既定値は0。総ページは開始ページより大きい整数です。現在ページ・総ページの未設定中は計算しません。
- 今日の日付はAsia/Tokyo。日付をUTCの整数日へ変換し、日付差のみを計算します。
- 必要ペースは残りページ÷残り日数。期限当日は1日、期限翌日以降は「目標日を超過」。開始当日の実績ペースも1日で割り、ゼロ除算を避けます。
- 理想進捗は開始日0%、目標日100%の線形計画。同日開始・目標は当日100%を理想とします。
- 矛盾のない履歴があれば開始日から最新記録日までの平均を使用。記録のない日も日数に含まれます。予測は今日から残りページ÷実績ペースの日数を切り上げます。
- 同じ日の更新は1件に集約。クイック記録はその日の時間・メモを保持。時間入力はその日の合計分数を上書きします。
- 過去履歴の編集・削除後は最新記録から現在ページを再計算。すべて削除すると開始ページに戻ります。履歴がある本の現在ページは履歴側で変更してください。
- ページが逆戻りする履歴は保存できますが警告し、今日までの平均へフォールバックします。時間あたりの指標は非表示になります。
- ページ/時間は「時間が正の記録日の増分ページ」÷「記録された合計時間」。時間が未記録の日のページは分子に含めません。
- グラフはSVG。日別系列は開始日〜今日または目標日まで（長い方）、無記録日0。累積進捗は記録位置と開始位置を結び、期限後の履歴も表示します。詳細な数値は履歴表で確認できます。

## 保存・復元

localStorageにバージョン1のJSONを保存。`store.js`をUIと分離し、将来の同期アダプターへ差し替え可能です。書き込み失敗時は画面のデータを更新しません。JSON復元は構造・日付・範囲・ID・重複・最新記録との整合性を検査し、確認後に全置換します（結合はしません）。ブラウザのサイトデータ削除・端末変更で消失するため、定期的にJSONを書き出してください。読み込み失敗時は元データを上書きせず、復元を待ちます。

## PWA更新

配信内容を変更したときは `sw.js` の `CACHE` のバージョンを変更してください。新しいService Workerは既存画面をすべて閉じた後に有効になります。再起動後、同じscopeの古いキャッシュを削除します。複数タブを開いている場合はすべて閉じてください。他のアプリのキャッシュは削除しません。

## 構成と検証

`core.js`: 日付・計算・検証 / `store.js`: 永続化 / `app.js`: UI・履歴・SVGグラフ / `sw.js`: オフライン / `core.test.js`: 自動テスト。

`npm test`で、0開始・途中開始・読了・期限超過・同日期限・進捗なし・誤入力・過去修正・複数書籍・月末年末・バックアップのケースを検証します。実機でのホーム画面追加・GitHub Pages実環境の公開確認は公開後に行ってください。

未実装（範囲外）: クラウド同期、認証、正答率・理解度、Anki連携。端末間・同一ブラウザの複数タブの同時編集は想定していません。
