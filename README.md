# 学習進捗トラッカー（周回管理版 / v2）

外部API・CDN・依存パッケージなしの静的PWA。書籍管理、通読/復習周回、履歴、SVGグラフ、学習時間、JSONバックアップに対応しています。表示上の日付はAsia/Tokyoです。

公開URL: https://hypoballad.github.io/study-tracker/
ソース: https://github.com/hypoballad/study-tracker

## 起動・テスト

Node.js 22以上。インストール不要です。

```sh
npm test
npm run build
npm start
```

http://127.0.0.1:4173/study-tracker/ を開きます。PORT環境変数でポートを変更できます。ファイルの直接オープンには対応しません。

## 周回の操作

1. 書籍設定で目標周回数（1〜100）と全周回の目標完了日を設定します。
2. 詳細の周回一覧で、未開始周回を「通読」または「復習」に設定します。開始後の種類は固定です。
3. 現在周回のページ/時間を記録。「現在周回を完了」で日付を指定し、確認後に保存します。
4. 「次の周回を開始」で、前周回の記録を保持して新しい周回を開始します。前の周回が未完了なら開始できません。
5. 周回一覧または選択欄から過去周回の履歴とグラフを閲覧・修正できます。

目標を減らしても周回や履歴は削除しません。総合進捗は全周回の達成率の合計÷目標周回数で、最大100%。目標外の過去周回も保持されます。

各通読周回には独立した開始/終了ページがあります。新しい周回の初期範囲は書籍の標準範囲です。書籍の標準範囲変更は未開始周回へ適用し、開始済みは周回設定から変更します。未設定だった終了ページは総ページ数入力時に補完します。既存履歴は書き換えず、不整合が生じる範囲の変更は拒否します。

復習は未完了0%・明示的完了100%。通読相当ページとページ/日のペースには含めず、時間だけを全体時間へ加算します。速度を理解度として表示しません。

## 計算と履歴

- 通読進捗 = (到達−開始)/(終了−開始)。0〜100%に制限。
- 全体の必要ペース = 目標内の通読ページ総量から累計通読実績を引いた残量÷期限までの日数。期限当日は1日、超過後は「期限超過」。復習の時間見積りは行いません。
- 実績ペース = 全通読周回の累計進捗÷書籍開始日から最新記録日までの日数。逆戻り履歴があると今日までの日数へフォールバックして警告します。分母は最低1日です。
- 現在周回の必要ペースは、その周回のみを全体期限までに終える参考値。全体必要ペースとは区別します。
- 予測は「現在周回の読了」「通読目標の完了」「総合周回完了」を区別。未完了の復習周回が目標内にある場合、総合予測は「算出不可」。
- 同一周回・同一日は1件に上書き。同日に別周回の履歴を作成できます。時間はその周回・その日の合計分数で、二重加算しません。
- 完了操作は通読の終了位置を記録し、既存の時間・メモを保持。復習は完了状態のみ更新します。
- 過去履歴の編集/削除で該当周回の現在位置を最新記録から再計算。終了位置より手前になれば完了状態を解除します。他周回の記録は変更しません。
- ページ/時間は時間が正の記録日のページ増分÷記録時間。未記録時間の日はページ増分を分子に含めません。部分的な時間記録では周回全体の速度を表さないため、比較時は時間の入力範囲を揃えてください。
- 累積グラフは各周回内のページ増分を日付別に合算。周回開始でゼロへ戻りません。日別の無記録日は0。周回別ページグラフも選択できます。1500日を超える期間は描画点を間引き、元履歴は保持します。

## データ移行とバックアップ

データ形式はversion 2。booksに目標数と現在周回ID、独立したrounds配列、logsにroundIdを追加しています。

初回起動時、旧キー`study-tracker-v1`を検証して全書籍を目標1周・現在1周へ移行。既存履歴はすべて1周目に割り当て、ページ・時間・メモ・IDを保持します。周回IDは決定的に生成し、v2を再読込しても重複しません。

旧キーは削除せず、`study-tracker-v1-before-v2`へ移行前JSONを退避し、`study-tracker-v2`へ保存します。保存失敗時は旧データを保持して編集を停止します。v2保存後はv2を優先し、旧キーは以後更新しません。

v1/v2両方のJSONをインポートできます。検証と上書き確認後に全置換します。定期的にJSONを書き出してください。ブラウザデータ削除や端末変更で端末内のデータは失われます。同じブラウザでの複数タブ同時編集やクラウド同期は対象外です。

## PWAと更新

PixelのChromeで公開URLを開き、メニュー → ホーム画面に追加 → インストール。一度オンラインで読み込んでからオフラインで利用してください。

Service Workerはv2.0.1。外部CDNなしで全実行アセットをキャッシュします。更新後はアプリのすべての画面/タブを閉じて再起動してください。新バージョンの初回読み込み後、もう一度閉じて開く必要がある場合があります。旧キャッシュは新SWのactivateで削除。端末データはキャッシュとは別に保持します。

配信内容変更時はsw.jsのCACHEバージョンを変更してください。ローカルのmanifestやSWのパスは相対パスで、Pagesのリポジトリ名変更に追従します。

## GitHub Pages

このフォルダの内容（`.github`を含む）をリポジトリ直下へ配置し、Settings → Pages → SourceをGitHub Actionsにします。mainへのpushでテスト→ビルド→dist公開を実行します。手動実行はActionsのDeploy GitHub Pagesから行えます。ブランチ変更時は`.github/workflows/pages.yml`を変更してください。

## ファイル構成

- core.js: 共通の日付・ページ進捗計算とv1検証。
- model.js: v2検証・移行・周回/全体集計・記録操作・グラフ系列。
- store.js: UIから独立した保存と自動移行。
- app.js: 既存デザインを維持したUIとSVG描画。
- model.test.js / store.test.js / core.test.js / pwa.test.js: 周回・移行・保存・既存計算・PWAの検証。
- build.mjs / sw.js: model.jsを含む静的ビルドとオフライン更新。

Android実機でのインストールとOSによる更新は実機確認が必要です。認証・クラウド同期・正答率・理解度・Anki連携は対象外です。
